# v4.4.0 — document → warehouse → deck skill chain

## Summary

This release adds a three-skill chain that documents the pipeline from
extracted CRE documents to institutional investment-committee decks. It
complements the AMOS prototype's IC-deck-generation work by giving Claude a
source-grounded, provenance-preserving path from raw document facts to
committee-ready slides.

The three new skills (all `category: reit-cre`, `status: deployed`,
`version: 0.1.0`) are:

1. **`document-to-warehouse-pipeline`** (domain `04-due-diligence`) — an
   orchestration skill that sits *above* the single-document extractors. It does
   not re-extract documents; it assembles the OUTPUT of the extractors into
   validated, warehouse-ready tabular datasets: multi-document assembly, declared
   extraction schemas, data-quality / validation rules, standardized provenance
   columns, warehouse table naming, and a deck-readiness gate that surfaces (does
   not silently drop) failing rows.
2. **`warehouse-to-exhibit-mapper`** (domain `02-underwriting-analysis`) — maps
   validated datasets to deck-ready exhibit specifications and slide inputs:
   table-vs-chart selection, axes/series, source-column-to-exhibit-field mapping,
   slide binding, and provenance carry-through so every exhibit cell keeps its
   `source_ref` + `classification`.
3. **`ic-deck-composer`** (domain `09-investor-relations`) — composes
   institutional committee decks following brand-guideline conventions
   (executive-summary-first, explicit decision ask, R/Y/G status, returns snapshot
   near the front, sources & assumptions visible, appendix / source-map). It
   documents all four deck families: Investment Committee (transaction approval),
   Valuation Committee (mark / valuation walk), Quarterly Business Plan / Asset
   Review (performance vs. plan), and Annual Business Plan (budget + strategy).

These are **documentation / skill-packaging skills**: they GUIDE Claude to
produce the artifacts described. They are not deterministic runtime engines —
there is no database, no charting library, and no slide renderer behind them, and
each SKILL.md opens by saying so. Each emits model-generated specifications a
human reviews and runs; none should be presented as machine-validated output.

## What changed

### New skills

- `src/skills/document-to-warehouse-pipeline/` — `SKILL.md` +
  `references/warehouse-schema-conventions.md` +
  `references/data-quality-rules.yaml`. Standardizes provenance columns
  `source_doc`, `locator`, `source_ref` (canonical join key
  `data-room/<doc>#<anchor>`), `extracted_by`, `classification`
  (`source-fact | calculated | modeled-assumption | requires-review`),
  `confidence`, `review_status`, `extracted_at`. Carries an explicit NEGATIVE
  trigger redirecting raw single-document extraction to
  `document-to-data-room-extractor`.
- `src/skills/warehouse-to-exhibit-mapper/` — `SKILL.md` +
  `references/exhibit-type-selection.md` +
  `references/field-mapping-patterns.yaml`.
- `src/skills/ic-deck-composer/` — `SKILL.md` +
  `references/deck-family-blueprints.md` +
  `references/committee-deck-conventions.md`. Negative triggers redirect memo
  PROSE to `ic-memo-generator` and LP-facing fundraising decks to
  `lp-pitch-deck-builder`.

## Maturity

The three new skills are documentation-level guidance, deployed and routed, but
they describe a workflow rather than execute it. Treat their output as proposed
specifications requiring human review — explicitly, do not present their
model-generated schemas, exhibit specs, or deck specs as machine-validated.
