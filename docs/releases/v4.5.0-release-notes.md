# v4.5.0 — Document-to-Database Ingestion Family

This release adds the first **executable** document-to-database ingestion family
to the plugin. Where the document → warehouse → deck skills (v4.4.0) GUIDE
Claude, this family is backed by real, deterministic, standard-library Python
calculators: it turns tokenized/extracted CRE documents into validated, typed,
auditable, target-model-ready database payloads, and it ties contractual
rent-roll charges to T-12 account-level actuals.

## What's new

### New skills (`category: reit-cre`)

- **`document-to-database`** — the ingestion orchestrator. Canonical flow:
  classify → identify fields → coerce → normalize → map charge codes to the
  chart of accounts → validate → score confidence → issue report → map to a
  target database model → emit optional SQL DDL + load plan → self-grade →
  route ambiguous items to human review. Ships ten shared reference docs
  (canonical schema, field dictionary, charge-code/account framework,
  target-model profiles, data-quality rules, human-review workflow,
  self-iteration loop, security/governance, known limitations, supported input
  formats).
- **`rent-roll-to-database`** — models a rent roll as a contract- and
  charge-level cash-flow source (multi-line charge schedule, escalations,
  recovery structure, unit/lease status), with GPR + occupancy reconciliation.
- **`operating-statement-to-database`** — the general operating-statement root
  (any line type / period grain / layout), with format-aware period handling,
  sign-convention normalization, duplicate/subtotal detection, and below-the-
  NOI-line enforcement.
- **`t12-to-database`** — a constrained preset over the operating-statement root
  (line_type = actual, trailing-twelve window; partial-year is a warning, never
  synthesized).
- **`rent-roll-t12-tieout`** — a basis-aware reconciliation (contractual vs
  accrual; collected cash out of scope) that classifies mapping/timing/missing,
  surfaces `residual_unexplained`, and never forces a tie.

### New calculators (`src/calculators/`)

`normalize_tokens`, `map_charge_codes`, `validate_payload`,
`reconcile_rent_roll_t12`, `map_to_target_model`, `emit_sql_ddl`,
`emit_load_plan`, `grade_ingestion`, `infer_schema` — each a pure
`calculate_<x>(dict)->dict`, plus a shared stdlib `ingest/` support package.

### Governance + quality

- Reuses (does not fork) the residential-multifamily GL crosswalk + GL schema,
  the rent-roll `data-quality-rubric.yaml`, and the extractor's
  `pii-redaction-policy.yaml`; parity is enforced by a sync test.
- Unit/tenant grain under a pseudonymized trust tier (locator-not-value); a
  PII-redaction breach is a non-overridable grade block.
- Weakest-link A/B/C grade (merge ≥ 85, production ≥ 92); a 0-100 score is
  secondary. Stateless / zero-data-retention: pure, stdlib-only, no wall clock
  (caller-supplied `as_of`), no network, stdout-only.
- Five target-model profiles (raw landing, normalized relational, star schema,
  data vault, hybrid recommended) with reviewable, DML-free Postgres DDL and a
  topologically-valid load plan (target-warehouse DDL; not executed).

## Testing

The family ships synthetic, clearly-fictional fixtures (rent rolls with and
without charge codes, T-12s with and without account codes, partial-year and
signed-negative statements, and clean / mapping / timing / missing tie-out
cases) plus test modules covering normalization, validation, charge/account
mapping, target-model mapping, DDL/load-plan, schema inference, reconciliation,
grading, PII redaction, determinism, and canonical-source parity. Run:

```bash
python -m pytest tests/test_ingestion_*.py
```

## Compatibility

No breaking changes. The new calculators and skills are additive; the catalog
counts regenerate from source.

## Known limitations

- Billed-vs-collected cash is out of scope (no AR feed); the rent roll is
  annualized contractual income.
- Recoveries and other income reconcile jointly because the canonical chart
  combines them in one account; the rent-roll-side breakdown is reported.
- Percentage-rent breakpoints and co-tenancy flags are carried where present but
  not projected into contingent-rent forecasts.
