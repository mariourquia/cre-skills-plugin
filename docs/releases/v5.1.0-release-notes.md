# v5.1.0 — Governance hardening (calculators, connector contracts, AMOS forward-compat)

## Summary

v5.1.0 is a hardening release. It does **not** grow the catalog (still 127 skills
/ 54 agents / 21 calculators / 10 orchestrators / 6 workflow chains — **0 net new
skills**); the value is correctness, truthful labels, and a more durable contract
surface for AMOS-style integration. It resolves the highest-priority v5.0.0
deferrals that could be delivered as a coherent, test-backed slice, and it is
explicit about what remains deferred.

This release does **not** add any live connector, live AMOS coupling, or
production runtime enforcement. Every connector contract is `status: stub`, the
AMOS manifest stays a static export (`live_connector: false` on every entry), and
the corpus-wide runtime governance scanner remains future work.

## What shipped (each landed with tests)

### Calculator fidelity
- **Monte Carlo beta-distribution copula fix.** Beta-distributed variables now
  inherit the Gaussian-copula correlation. Previously the beta branch drew an
  independent `rng.betavariate()` and silently discarded the `correlation_matrix`
  while a comment falsely claimed correlation was preserved. The fix adds a
  regularized-incomplete-beta inverse CDF (`beta_invcdf`, stdlib-only, with the
  symmetry transform for `alpha/beta < 1` and endpoint clamping) and extracts the
  per-trial sampler into `sample_trial_values`. New tests prove sign-correct
  correlation (n=6k, fixed seed), marginal-mean preservation, closed-form
  quantiles, endpoint/`alpha<1` robustness, and determinism.
- **`fund_fee_modeler` honest labels.** The promote-sensitivity output is labeled
  `grade: screening` + `method: linear_fee_drag_approximation`; the
  `breakeven_irr_*` values are a linear fee-drag approximation, **not** a
  discounted-cashflow IRR. The numeric keys are preserved (non-breaking).
- **`debt_sizing` interest-only clarity.** Non-breaking `interest_only` alias keys
  alongside the `_io` abbreviations (math unchanged).
- **Value-domain refusals.** `transfer_tax`, `proration_calculator`, and
  `quick_screen` now return typed refusal envelopes on value-domain degeneracy
  (non-positive price, unmodeled state, **unparseable date** — previously a raw
  traceback — closing outside the tax year, negative basis) instead of negative or
  fabricated output. Registered in the degenerate-input contract.

### Connector contract schemas + `source_class` hardening
- **Four canonical connector contract schemas authored as stubs:** `debt` (loan),
  `entity` (legal/ownership cap-structure — explicitly distinct from the
  operational `master_data` connector), `valuation`, and `funds` (fund +
  pseudonymized `investor_report`, folding in investor reporting). Each conforms
  to the existing connector meta-schemas with the 6-field provenance,
  `source_class`, `max_staleness`, generic reconciliation checks, and
  round-tripping `sample_input` / `sample_normalized` payloads.
- **`source_class` is now a schema-enforced enum.** The canonical six-value list
  lives in `reference/connectors/_schema/source_class.yaml`, is wired into
  `entity_contract.schema.yaml`, and is validated by
  `tests/test_connector_source_class.py` (schema-enum == canonical list; every new
  contract declares a canonical `source_class`). The 8 legacy stubs are
  unaffected — the field is optional on the meta-schema.

### AMOS forward-compatibility
- The skill-manifest now emits three forward-compat fields per skill —
  `produces_artifact_kind`, `pii_policy` (conservative default `none`,
  explicit-opt-in so it never over-claims PII handling), and `workspace_scope` —
  so AMOS can consume them. `live_connector` stays `const: false`. A new
  `--emit-sample` mode regenerates the committed sample deterministically.

## What is still deferred (honest)

- **Corpus-wide runtime governance scanner.** Decision-grade enforcement at emit
  time remains deployed **only inside `residential_multifamily`**; elsewhere the
  named-allowlist finance-placeholder guard is a presence-of-discipline check, not
  a runtime scanner. Generalizing the RMF runtime machinery to the whole corpus is
  future work.
- **Full 127-skill `v5_contract` conformance.** Still a pilot (the opted-in slice
  plus the decision-grade / AMOS-facing allowlist enforcement). The full-corpus
  section sweep is future work.
- **Live connectors / runnable adapters.** The four new contracts are `status:
  stub`. No adapter executes; `source_class`/`max_staleness` are declared and
  schema-validated, **not** enforced at a connector runtime. Valuation and
  investor-reporting *runnable* adapters remain future work.
- **AMOS field population.** `produces_artifact_kind` / `pii_policy` /
  `workspace_scope` default to `null` / `none` for every skill; per-skill
  population from SKILL.md frontmatter (and `outputs[]` backfill) is future work.
- **Windows `.exe`.** Still produced on CI / Windows only (Inno Setup,
  `scripts/create-exe.iss`); it cannot be built on the macOS dev host. See
  `docs/known-limitations.md`.
